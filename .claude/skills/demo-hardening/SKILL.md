# Demo Hardening

The judges will hand us a fresh, ugly input, or change one field in a staged
one. Assume adversarial-by-accident, not malicious.

## The mutation list (run these against `scripts/demo.sh` before rehearsing)
For each input source (Slack export, email, support ticket, press):
1. **Missing field** — drop `user`, `ts`, `subject`, `thread_id`. One at a time.
2. **Null / empty string** where a value is expected. Empty message body.
3. **Wrong type** — number where string expected, string where list expected.
4. **Weird encoding** — emoji, non-ASCII names, smart quotes, RTL text, `\u0000`.
5. **Format drift** — different timestamp format (epoch vs ISO vs "2h ago"),
   different date order, extra unexpected keys.
6. **Volume edges** — zero records, one record, a 10k-char message, 500 records.
7. **Duplicate / near-duplicate** records (same content, different id).
8. **Broken references** — thread_id pointing at nothing, unknown user id,
   @mention of someone not in the roster.
9. **Conflicting facts** across two sources (this is a FEATURE — the pipeline
   should flag the conflict, not pick silently).
10. **Ambiguity** — a message that could belong to two projects.

## Rules for handling each
- Never crash the whole run. Per-record try/except; log `id + reason`; continue.
- Never silently drop. Every skipped record appears in the output as
  "N records unprocessed: <reasons>". Judges read that as rigor.
- Never silently pick between conflicts. Surface both with sources.
- Degrade gracefully: missing optional field → note it and proceed; missing
  required field → skip that record loudly, keep the rest.
- Attribution always: every claim in the briefing cites which message/email
  it came from. Unsourced claims are hallucinations waiting to happen.

## LLM-specific hardening (the extraction step)
- Force structured output (JSON schema), validate it in code, retry ONCE on
  invalid JSON, then skip loudly. Never trust the model's shape.
- Cap input size per call; chunk deterministically; never let one huge message
  blow the context.
- If the model returns a fact not present in the source text, that's a bug —
  prefer extraction prompts that require verbatim evidence spans.
- Handle API failure: retry with backoff once, then surface "source X
  unavailable" in the output rather than pretending it was empty.

## Rehearsal protocol
Run `scripts/demo.sh` end to end at least 3x on inputs nobody rehearsed,
generated by a teammate. Time it. If it takes >90s, cut work, not correctness.
